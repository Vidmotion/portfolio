# DESIGN BRIEF — Creative Brief

> **Version:** 2.0
> **Status:** Pre-Production
> **Last Reviewed:** 2026-06-29

---

## Purpose

This document defines the complete creative brief for Portfolio OS.

It is written specifically for designers and Claude Design.

Its objective is to communicate the vision of the project before any visual exploration begins.

This document intentionally avoids implementation details.

Technology does not define this project.

The experience does.

The goal is to create a complete design system and user experience that can later be implemented with precision.

---

# Project Overview

Portfolio OS is not a traditional website.

It is a premium digital experience inspired by the interaction philosophy of Apple's operating systems.

Visitors should immediately feel that they have entered Carlo Desantis' personal creative workspace.

The operating system becomes the interface.

The portfolio becomes the content.

Every design decision should reinforce this illusion.

---

# Project Vision

The objective is to create one of the most refined creative portfolios on the web.

The experience should feel:

Native.

Elegant.

Timeless.

Confident.

Minimal.

Premium.

Purposeful.

Every interaction should communicate intention.

Nothing should exist purely for decoration.

The interface should disappear behind the creative work.

---

# Primary Goal

Present Carlo Desantis' creative work through an operating system experience that feels natural, memorable and effortless.

The experience should remain intuitive even for users who have never seen the portfolio before.

Users should understand the interface almost instinctively.

---

# Brand Positioning

Carlo Desantis is a filmmaker, photographer and creative director.

The portfolio should communicate craftsmanship rather than self-promotion.

It should feel like entering the workspace of someone deeply passionate about visual storytelling.

The interface should express confidence through restraint.

Never through excess.

---

# User Experience Vision

The visitor should feel curious from the very first second.

Instead of navigating pages,

they explore a digital workspace.

Instead of scrolling,

they open applications.

Instead of clicking menus,

they interact with a familiar operating system.

The experience should feel playful without becoming distracting.

---

# Emotional Goals

The interface should evoke:

Curiosity

Wonder

Calm

Trust

Craftsmanship

Precision

Exploration

Creativity

Authenticity

Confidence

The experience should never feel:

Chaotic

Overwhelming

Confusing

Aggressive

Noisy

Artificial

---

# Design Philosophy

The operating system is only a medium.

Creative work remains the protagonist.

Every visual decision should strengthen the projects rather than compete with them.

The experience should reward exploration.

Visitors should naturally discover projects through interaction rather than through traditional navigation.

---

# Experience Principles

The design should feel:

Native before decorative.

Simple before complex.

Purposeful before expressive.

Consistent before surprising.

Elegant before impressive.

Fast before flashy.

Readable before experimental.

Timeless before trendy.

---

# Platforms

The project consists of three independent experiences.

Desktop

The primary experience.

Inspired by macOS.

Tablet

An adaptation of the desktop experience for touch interaction.

Not simply responsive.

Mobile

A completely different interface inspired by iOS.

The mobile experience begins with a lock screen before entering the home screen.

---

# Creative Direction

The visual identity should communicate maturity.

Avoid futuristic clichés.

Avoid excessive skeuomorphism.

Avoid nostalgic operating system recreations.

The experience should feel modern.

Refined.

Minimal.

Original.

---

# Interaction Philosophy

Interactions should feel predictable.

Users should always understand what is happening.

Motion communicates state.

Windows communicate hierarchy.

The desktop communicates freedom.

The experience should encourage exploration without requiring explanation.

---

# Content Philosophy

Projects are always the hero.

The interface introduces the work.

Then disappears.

Photography deserves its own dedicated experience.

Notes communicate personality.

Widgets create life.

Folders organize exploration.

Applications become stories.

---

# Motion Philosophy

Motion should feel inspired by Apple's interaction philosophy.

Animations should communicate:

State

Hierarchy

Navigation

Focus

Continuity

Never animate simply to impress.

Every animation should have purpose.

---

# Visual Direction

The interface should feel lightweight.

Glass should feel subtle.

Blur should support hierarchy.

Shadows should communicate elevation.

Whitespace should create rhythm.

Typography should remain effortless.

Nothing should feel visually heavy.

---

# Deliverables

Claude Design should produce a complete production-ready Figma workspace.

The output must include:

Design Foundations

Variables

Typography

Color System

Spacing System

Effects

Glass Materials

Elevation System

Component Library

Desktop Experience

Tablet Experience

Mobile Experience

Interactive Prototypes

Developer Handoff

No static mockups.

Everything should be reusable.

Everything should be component-based.

Everything should be built using Auto Layout and Variables.

---

# Success Criteria

The design process is successful when:

The interface feels like a premium operating system.

The projects remain the protagonist.

The interaction feels effortless.

The design system is scalable.

Every screen is built from reusable components.

The design can be implemented with precision by Claude Code.

The final product feels original while clearly reflecting the quality standards of modern Apple software.

---

# Final Statement

Portfolio OS should not be remembered because it resembles an operating system.

It should be remembered because the operating system became the most natural way to experience Carlo Desantis' creative world.

Every design decision should reinforce that objective.

Nothing else.

# PROTOTYPE FLOW — Interaction Flows

> **Version:** 2.0
> **Status:** Pre-Production
> **Last Reviewed:** 2026-06-29

---

## Purpose

This document defines every interaction flow that should be prototyped inside the Figma workspace.

The objective is to validate the complete user experience before development begins.

Prototype interactions.

Not static screens.

Every meaningful action inside the Portfolio OS should be represented through interactive prototypes.

---

# Philosophy

The prototype should feel like using a real operating system.

Users should understand the experience through interaction.

Not explanation.

The prototype should communicate rhythm.

Motion.

Hierarchy.

Continuity.

Confidence.

# Platform Transitions

Demonstrate Portfolio OS across its three distinct experiences:

Desktop (macOS-inspired)

Tablet (iPadOS-inspired)

Mobile (iOS-inspired)

Each experience has its own interaction model.

The visual identity remains consistent across all three.

Desktop, Tablet and Mobile are not responsive variants. Each is designed independently.

---

# Prototype Review

Every prototype should answer one question:

Does this interaction feel natural?

If not,

simplify it.

Never add complexity to compensate for weak interaction design.

---

# Definition of Done

The prototype is complete when:

Every major user journey has been demonstrated.

Every operating system interaction has been validated.

Motion communicates hierarchy.

Navigation feels intuitive.

Desktop, Tablet and Mobile experiences are represented.

The prototype can be used as the definitive interaction reference for engineering.

Claude Code should be able to understand every interaction simply by observing the prototype.
